Formula

Bytes = value × basesource level; target value = bytes ÷ basetarget level, where levels are B=0, KB=1, MB=2, GB=3, TB=4.

Strictly, KiB/MiB/GiB are the base-1024 units and KB/MB/GB are base-1000 SI units. In practice many operating systems label base-1024 sizes as KB/MB/GB; this page follows that common labelling and lets you switch base explicitly instead of hiding the difference.

Worked example

1 GB at base 1024 = 1 × 1024 = 1,024 MB, = 1,024 × 1,024 = 1,048,576 KB, = 1,073,741,824 bytes. The same 1 GB at base 1000 = 1,000 MB exactly. A 2.5 TB drive at base 1024 is 2.5 × 1,024 = 2,560 GB.

Scope and limitations

Negative sizes are rejected as invalid. Display values are rounded to 6 decimal places; the underlying calculation is not rounded. Formatted drive capacity, filesystem overhead, and the KiB-vs-KB naming dispute are not modelled — this page converts the number you enter, nothing more.

FAQ

Should I use base 1024 or 1000?

Use 1000 for SI/manufacturer specifications (a drive sold as 1 TB usually means 10^12 bytes) and 1024 for the sizes most operating systems report. When in doubt, check which one your source used — the gap reaches about 10% at TB scale.

What is the difference between GB and GiB?

GiB is unambiguously base 1024 (1 GiB = 1,073,741,824 bytes); GB is the SI base-1000 unit. Many tools write GB when they mean GiB, which is why this page makes the base an explicit choice.

Why does my 1 TB drive show less than 1 TB?

Partly this base difference: 10^12 bytes = 931.32 GiB at base 1024. Filesystem overhead accounts for the rest.

How many MB in a GB?

1,024 MB at base 1024, or 1,000 MB at base 1000 — the answer depends on the base, so always state it.

Does this handle bits?

No — bytes only. 1 byte = 8 bits; convert bits to bytes first (divide by 8) and enter that value.
